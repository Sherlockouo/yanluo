# Jobs 设计原则 — 言落 (Yanluo)

> 权威 UI 原则。改界面前先读；细则见本文件，会话强制约束见 `.cursor/rules/jobs-design.mdc`。

## 一句话

**做更少，做到极致。布局即说明。一屏一事。**

## 核心原则

### 1. Focus as subtraction

- 每屏只服务一个主任务。其余收进次级入口或设置。
- 互斥状态不要并排：上传 / 处理中 / 结果；配置 / 学习闭环 —— **同一时间只突出一个**。
- 删文案优先于加控件。图标 + 布局能说清的，不要写「如何使用」段落。

### 2. Hierarchy（主次）

- **一级**：当前任务本体（标题 + 主操作或主内容）。
- **二级**：支撑该任务的单一面板。
- **三级**：统计、次要按钮、历史碎片 —— 视觉降权（字号、对比度、位置），不要和一级抢视线。
- 禁止：左右双栏同等权重、按钮条排满、同屏多组「主色 CTA」。
- **配置不垫底**：结果/列表页的配置从**页头次级按钮**展开到标题下方；禁止塞在可滚动结果列表末尾（坟场）。深度项进设置。

### 3. Layout is the instruction

- 不要图例（「红为原文…」「上为原文…」）。
- 一种语义一种形态：refine = 内联画线；翻译 = 上下语义对照（无标签）。
- 空态一句够；不要空态散文。

### 4. Restraint

- 一种强调色（accent）只用于真正主操作。
- 卡片不堆叠解释块；能用一行状态就不要用段落。
- 密度：工具感可以密，但**焦点区必须留白**，别把修正框 / Prompt / 统计挤成一坨。

### 5. Motion

- 只服务理解：换页、展开、状态切换。
- 仅 `opacity` + `transform`；短（≤220ms）；禁止为炫技 stagger。
- **Tab/Mode：enter-only**。禁止 `mode="sync"` 进出叠流（残影）。
- 详见 [`architecture-local-first.md`](./architecture-local-first.md) 动效条款。

## 对本产品的硬规则

| 页面 | 一屏一事 |
|------|----------|
| 概览 | 模型未就绪 → 安装；否则转写 + Agent 入口（非功能网格） |
| Agent | **任务列表优先**；页头「配置」profile（kind/bin/model · which）·「召唤」；Fn+Space → floating HUD 语音 + 编辑派发 |
| 转写 | **结果优先**（有历史默认结果）；上传 / 处理中 / 结果互斥；上传经「新转写」 |
| 翻译 | **结果优先**；页头「配置」展开目标语/Prompt（标题下，非列表底） |
| ASR | **结果优先**；页头「引擎」展开模型/VAD；需下载时自动展开；深度进设置 |
| LLM | **学习 case 优先**；页头「配置」展开纠错开关/模型/Prompt；未就绪默开配置 |
| 词库 | **词条列表优先**；页头「添加」展开输入（空态默开） |
| 历史 | 浏览与展开；清理为次级 |
| 设置 | 系统项；ASR/LLM 详情链到专页；Agent 配置在 `/agent` |

## 反例

- 左右双栏：左配置 / 右学习闭环 —— 无主次。
- 统计条 + 三组按钮 + case 卡内 ASR/LLM/用户修正/评分 —— 同屏噪音。
- 长说明：「学习三元组…」—— 布局应自解释。
- **结果列表底下挂「配置」折叠** —— 滚到坟场才找到；正常人/Jobs 不会这么做。

## 改 UI 检查清单

- [ ] 用户 3 秒内能说出「这页要我干什么」？
- [ ] 是否只有一个视觉主操作？
- [ ] 删掉所有「解释 UI 怎么工作」的句子后，还能用吗？
- [ ] 次要信息是否降权（muted / 更小 / 折叠）？
